# DB のバックアップと復元

会話の履歴は、艦ごとの `{艦のディレクトリ}/data/bridge.db`（SQLite）にあります。

## バックアップ

1. 艦のサーバーを止めます。
2. `data/bridge.db` を、別の場所へコピーします（強制終了のあとは、下の注意のとおり、`data/bridge.db*` をまとめて）。

   ```
   cp data/bridge.db /path/to/backup/bridge-$(date +%F).db
   ```

艦を、`Ctrl+C`（または `SIGTERM`、設定画面の「停止」）で止めると、終了のときに、書き込みの記録（`bridge.db-wal`）を `bridge.db` に取り込んでから閉じます。この場合は、**そのファイル 1 つで完全なバックアップ**です（`-wal`・`-shm` は不要です）。

**強制終了（`kill -9`・電源断・クラッシュ）のあとは、そうとは限りません。** 取り込まれていない分が、`bridge.db-wal` に残っています。その場合は、`bridge.db` だけでなく、**`data/bridge.db*` をまとめて**コピーしてください（または、艦をもう一度起動して、`Ctrl+C` で止め直してから、コピーしてください）。

## 復元

1. 艦のサーバーを止めます。
2. 古いファイルを、`-wal`・`-shm` ごと退避して、バックアップを置きます（古い `-wal` は、古い `bridge.db` のものなので、バックアップの `bridge.db` と組み合わせてはいけません）。

   ```
   mkdir data/old
   mv data/bridge.db* data/old/
   cp /path/to/backup/bridge-2026-01-01.db data/bridge.db
   ```

3. サーバーを起動します。古い版のバックアップなら、起動時に自動で最新の版へ移行します。

## マイグレーション前の自動バックアップ

アップデートでデータベースの構造が変わるとき、書き換える前に、`data/bridge.db.bak-v<旧版>` へ自動でコピーします。同名があるときは、末尾に時刻を付けます（上書きしません）。古いものは、自動では消えません。

- アップデート後に、前の版へ戻したいときは、前の版のプログラムに戻し、`.bak-v*` を `bridge.db` として置きます（上の復元の手順）。
- **このプログラムより新しい版の DB は、何も変更せずに、エラーで起動しません。** 新しい版で作った DB を、古い版のプログラムで壊さないためです。

詳細は[データモデル](../reference/data-model.ja.md#マイグレーション)を参照してください。
