# Memory を使う

Memory は、艦の共有ノートです。クルーが、何かを学んだり決めたりしたときに書く短い Markdown のメモで、あなた（と、あとの会話やミッションでのクルー全員）が、もう一度見つけられます。ミッションではなく、艦に属します。

## 読む

ヘッダーの「Memory」を押します。右にペインが開き、ウィンドウの半分を使います（左の端をドラッグして変えられます。選んだ幅は覚えます）。一覧とメモの境界をドラッグすると、それぞれの広さを変えられます（上下と左右で、別々に覚えます）。

- 上半分は一覧です。ディレクトリ（押すと開く）とメモが並び、下書きと非推奨のメモには印が付きます。検索ボックスに入力すると、代わりにタイトル・説明・本文を検索します（すべての語が一致すること。先頭の 32 語まで。1〜2 文字の語は先頭の 4 語まで。日本語も使えます）。
- 下半分は、選んだメモです。書いたクルーと日時、説明、本文が出ます。「先頭部分(frontmatter)」を開くと、ファイルの先頭にあるヘッダーがそのまま見えます。ほかのメモへのリンクはペインの中で移動します。Web のリンクは新しいタブで開きます。
- ペインの右上のボタンで、一覧をメモの上に置くか、横に置くかを切り替えられます。
- 「下書き」と「非推奨」で、その種類のメモを、一覧に出す・出さないを切り替えます。
- 幅 860px 以下のウィンドウでは、ペインがページ全体を覆います（Esc か × で閉じます）。

クルーが書くと、ペインはひとりでに更新されます。ペインからはメモを編集できません。変えたいときは、クルーに頼んでください。

## クルーがすること

クルー全員に、組み込みのスキル `memory` があります。いつ書くか（学びのあったタスクの終わり、決定とその理由、あなたに「覚えておいて」と頼まれたとき）、メモの名前と説明の付け方、そして、すでに知られていそうな作業の前に Memory を見ることが書いてあります。クルーは、[MCP 掲示板](../reference/http-api.ja.md#mcp-掲示板)の次のツールを使います（リモートホストのクルーも同じです）。

| ツール | できること |
|---|---|
| `search_memory`、`read_memory` | メモを探す・読む |
| `write_memory` | メモを作る・更新する。書くたびに、一言のメッセージを付ける |
| `deprecate_memory` | メモは残すが、もう従わないものとして印を付ける（後継も伝える） |
| `delete_memory` | メモを消す（履歴は残る） |
| `get_memory_history` | 誰が、いつ、何を、なぜ変えたか。最近の変更の要約は、クルーに頼む |

- メモには、次のものがあります。
  - 1行の `description`（説明）。
  - フラグ。必要なときだけ付けます。走り書きなら `draft`、古くなったら `deprecated` です。フラグのないメモは、確定したものとして扱います。
  - タグはありません。メモは置き場所（ディレクトリ）で整理するので、どこに置くかを選んでください。
  - `type`。サーバーがいつも `note` と書きます（OKF が必須としているためです）。手で書いたファイルの `type` はそのまま残ります。
  - キーは英語です。タイトル・説明・本文は、クルーが話す言語で書きます。
- クルー同士が、お互いの書き込みを上書きすることはありません。メモを更新するクルーは、読んだときの版を渡し、古い版は、今のメモをつけて断られます。
- 厳しい上限はありません。メモが 1MB を超える、または Memory が 50,000 件を超える書き込みも、成功し、警告を返します。クルーは、その警告をあなたに伝えるよう教えられています。
- 変更を元に戻すときは、クルーに頼みます。履歴から古い本文を読み、書き戻します。

## どこにあるか

`ships/<艦>/knowledge/` が、[Open Knowledge Format](https://github.com/open-knowledge-format/open-knowledge-format)（v0.3）のバンドルです。YAML のヘッダーが付いた、ふつうの Markdown ファイルで、専用の git リポジトリでもあります（変更1回が1コミット。作者はクルー、メッセージもクルーのものです）。どんなツールでも読んで、コピーでき、どのエディタでも開けます。

- `index.md`（各ディレクトリの目次）は、変更のたびに、サーバーが書きます。直さないでください。
- 手で直したファイルは、次に艦を起動したときに拾います。そのメモ自体に次の変更があるときに、その変更と一緒に、書いたクルーの名前でコミットされます。手で消したファイルは、git の履歴のツリーに残ります。
- 検索の索引は、艦の DB にあり、起動のたびにファイルから作り直します（[データモデル](../reference/data-model.ja.md#memory-の索引)）。消しても、何も失いません。

## OKF との関係

Memory は [OKF](https://github.com/open-knowledge-format/open-knowledge-format) v0.3 に沿っています。ただし2つのキーは、OKF より限って使います。

- **`tags`**: OKF では任意のキーです。Memory では使いません。手で書いたタグはファイルに残りますが、読み込みません。
- **`type`**: OKF では必須のキーです。サーバーがいつも `note` と書きます。手で書いたファイルの `type` はそのまま残ります。

OKFに `tags` と `type` があるのは、整理された大量の文書をプログラムが種類ごとに分けるためです。Memory は、思いついたときに書いて気軽に消すノートです。1つのメモに手順と決定の理由と既知の問題が一緒に入ることもよくあります。そこにタグや `type` を足しても、ディレクトリとは別のあいまいな分類が増えて、メモはかえって散らばります。そのため分類はディレクトリだけにしました。OKFはこれを許しています。`type` の値は自由で、決まった一覧を求めていないからです。
