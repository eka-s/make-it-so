# デスクトップアプリを使う

デスクトップアプリは、艦を専用のウィンドウで開きます。艦の画面はポートでは配信しないので、ブラウザから届くものはありません。（クルーが呼ぶ掲示板の MCP は、今までどおり `127.0.0.1` で待ち受けます。ポートは起動のたびに OS が選び、全セッションに渡す秘密の値が要ります。）

## 開いたときの動き

- **艦がちょうど1隻:** すぐに開きます。
- **艦が複数、または0隻:** 一覧が出ます。艦を選ぶと、その艦が専用のウィンドウ（Dock のアイコンも別）で開き、一覧は閉じます。一覧の**設定**ボタンで、艦を作る設定画面を開けます。
- **艦がすでに開いている:** 同じ艦をもう一度開くと、2つ目は起動せず、そのウィンドウが前に出ます。
- **艦のウィンドウを閉じると、その艦は止まります。** クルーのセッションも一緒に終わります。
- **設定:** 一覧から、または艦のウィンドウのメニュー項目（macOS は `⌘,`）から開きます。設定の「艦」タブには、起動と停止の代わりに**艦を開く**ボタンがあります。開いている艦の削除は、拒否されます。
- **ヘッダーがタイトルバーです。** ウィンドウに、専用のタイトルバーはありません。macOS では、ウィンドウのボタンが、ヘッダーの左端に出ます。Linux では、アプリが、右端に、テーマの色で描きます。その隣の **⋮ ボタン**が、アプリのメニューを開きます（クリックできるメニューバーがないためです。中身は、File（艦の窓では設定と終了）、Edit、View、Window のメニューです）。ヘッダーをドラッグすると、ウィンドウを動かせます。
- **テーマと言語:** 艦のウィンドウの表示メニュー（テーマ、UI の言語、クルーの言語）と、設定ウィンドウの表示メニュー（テーマと UI の言語）から選べます。艦の一覧には、この表示メニューはありません。選んだものは、左ペインの「設定」区画のラジオボタンと同じ形で反映されるので、同じ場所に保存されます（テーマはウィンドウのブラウザ保存、言語は艦。設定ウィンドウは、自分の言語の選択を持ちます）。メニューの言葉は、ページの言語に合わせて変わります。
- **ウィンドウは狭くできます:** 艦のウィンドウは、スマホくらいの幅（拡大していないときは、macOS は375px、Linux は463px。Linux はウィンドウのボタンの余白を取るためです。拡大すると、その分広くなります）まで狭くできます。幅860px未満では、左ペインが、会話の上に重なるドロワーになり、ヘッダーの左のボタンで開きます。幅600px未満では、入力欄の横のボタンが、メニューの中に入ります（[画面の構成](../reference/behavior.ja.md#画面の構成)）。

ファイルは今までどおり `~/.make-it-so` にあります。デスクトップアプリとブラウザ版は、同じ艦を読みます。**1つの艦は、どちらか一方でしか開けません**。片方で動いている艦を、もう片方で起動すると、メッセージを出して断ります（先に、ウィンドウを閉じるか、ブラウザ版を止めてください）。どちらの版の設定も、もう一方で開いている艦を、動いているものとして数えるので、そこから、二重に起動したり、削除したりはできません。

## ソースから動かす

```
npm run build
npm run start:electron                 # 上のとおり（艦、一覧、設定のどれか）
npm run start:electron -- --ship alpha # 艦を1隻
npm run start:electron -- --settings   # 設定
```

## アプリを作る

```
npm run pack   # release/mac-arm64/Make-It-So.app（インストーラーにはしない）。Linux は release/linux-unpacked/
npm run dist   # release/Make-It-So-<バージョン>-arm64.dmg。Linux は release/Make-It-So-<バージョン>-x86_64.AppImage
```

アプリには**署名がない**ので、ダウンロードしたファイルから開くと、macOS が警告することがあります。署名と公証には Developer ID の証明書が要りますが、ここでは用意していません。これまでに、ビルドして動かしたのは、macOS（Apple シリコン）と、Linux（x64。AppImage）だけです。

## リリースする

`package.json` の `version` と一致するタグ(例: `v0.1.0`)を push すると、Release ワークフローが動きます。検査のあと、macOS(dmg)、Windows(NSIS のインストーラー)、Linux(AppImage)でビルドして、3つとも GitHub の**下書き**リリースに添付します。生成されたノートを確認して、手で公開してください。どれも署名がありません。Windows のビルドは、まだ実機で動かしていません。
