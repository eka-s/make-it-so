# 画面の挙動

Web UI が守る挙動の約束です。**見た目（色・寸法・時間・書体）は含みません。** 見た目は変わりえますが、ここに書いた挙動は、変えるなら文書も一緒に直します。

## 基本方針

- クライアントは、サーバーが返したものをそのまま描画します。値を推測・変換・合成して作り直しません（[概念](../concepts.ja.md)）。
- 会話の表示は、`GET /api/timeline` のスナップショットと、SSE の `timeline:upsert` / `append` / `remove` だけから作ります（[HTTP API](http-api.ja.md#sseサーバー送信イベント)）。
- SSE は全ミッションの分が同じ経路に流れます。クライアントは、**今開いているミッションと違うミッションのイベントを、会話の表示には使いません。** クルーステータスの更新の合図だけは、ミッションを問わず受け取ります。
- 日時は、ブラウザのローカル時刻で表示します。

## ブラウザに保存するもの

次のものだけを、ブラウザの `localStorage` に保存します（個人用の表示設定。サーバーには送りません）。

| キー | 内容 |
|---|---|
| `active-mission-id` | 選択中のミッション |
| `chat-default-target:<ミッションID>` | ミッションごとの、基本の話し相手 |
| `chat-target-order` | 話し相手ボタンの並び順 |
| `search-group-mode` | 検索結果のまとめ方 |
| `left-panel-width` | 左ペインの幅 |
| `chat-split-enabled` | 会話の上下分割の有効／無効 |
| `chat-split-ratio` | 上下分割のときの、上画面の高さの割合 |
| `left-section-height-mission`・`-crew`・`-accounts`・`-pin` | 左ペインの各区画の高さ |
| `language-cache` | 画面の言語（サーバーの値の写し。最初の描画で、言語がちらつかないように） |
| `settings-language-choice` | 設定画面の言語（設定画面で選んだもの。サーバーには送らない） |

- 保存した値が今の艦の構成・一覧に存在しないとき（クルーの編成を変えた、DB を作り直した、など）は、次の値に戻します。
  - 話し相手: 艦の既定の話し相手（副長がいれば副長、いなければ最初のクルー）
  - ミッション: 既定のミッション（`bridge`）
- `localStorage` が使えなくても、保存できないだけで動作します。

## 画面の構成

- 左ペイン、会話、入力欄、ヘッダーからなります。
- ヘッダーには、左から、タイトル、検索ボタン、分割ボタン、言語の表示があり、**右端に艦の名前**が出ます（複数の艦を開いているとき、タブがどの艦のものかが分かります）。
- 言語の表示（たとえば `EN / 日本語` は、UIの言語、クルーの言語の順）は、控えめにしてあります。ホバーすると意味が出て、クリックすると、2つのスイッチの小さなポップアップが開きます（[言語を切り替える](../guides/switch-language.ja.md)）。
- 左ペインは、幅を右端のドラッグで変えられます。中の区画は、それぞれ独立して開閉できます（複数を同時に開いたままにできます）。開いた区画は、下端のドラッグで高さを変えられますが、**中身がすべて見える高さより大きくはできません。**
- 左ペインの区画（上から）:

| 区画 | 既定 | 内容 |
|---|---|---|
| ミッション | 閉じている（選択中の 1 件だけ見える） | [ミッションの一覧](#ミッションの一覧) |
| クルーステータス | 開いている | [クルーのステータス](#クルーのステータス) |
| PIN | 閉じている | 今のミッションの PIN |
| アカウント | 開いている | [使用量の表示](#使用量の表示) |

## 会話の表示

### 発言の表示

- 発言は時系列に並びます。艦長の発言とクルーの返信は、見た目で区別します。
- 返信は Markdown として表示します。艦長の発言は、書いたままの改行で表示します。
- 返答の途中（`streaming`）のものは、本文が伸びていきます。完了・失敗・中止は、それぞれの状態で表示します。中止された返答は、途中までの本文を残し、中止であることを示します。

### 長い発言の折りたたみ

- 本文が一定の行数を超えると、頭から切って「全文を表示」ボタンを出します。押すと展開し、「折りたたむ」で戻ります。
- 展開の状態は、SSE による更新をまたいで保持します。画面の再読み込みや、部品の作り直しでは、折りたたみに戻ります。
- 表示領域の大きさが変わったとき（ウィンドウ幅の変更など）は、超過しているかどうかを測り直します。
- **返答の途中**は、決まった高さの窓の中で本文が末尾に追従してスクロールします。完了すると、折りたたみの表示に戻ります。
- タスクのカードの折りたたみ位置は、通常の発言の半分です。

### クルーのタスク

- 同じターンで発行されたタスクは、1 枚の「Crew reports」カードにまとまります。
- 実行中のクルーごとに、通常の会話と同じ表示（考え中の表示と、発言のカード）を、カードの中に入れ子で出します。複数のクルーが動いていれば、その人数分が並びます。
- 発言のカードの本文は、決まった高さの窓の中でスクロールします。
- **指示**は、カードの中の「指示」で開閉できます。
- 完了しても、バッジに縮まず、同じカードのまま残ります。
- タスクのキャンセルは、発言のカードの停止ボタンで行います。
- 見出しにマウスを載せると、タスクの報告のポップアップを開くボタンが出ます。

### 履歴の読み込み

- 初めに、新しい側の一定件数を読み込みます。上端に古い履歴があるときは、「古い発言を読み込む」ボタンを出します。
- 一番下にいる間は、新しい発言や本文の伸びに合わせて、下へ自動でスクロールします。
- 会話の右下に、「一番上へ」「一番下へ」のボタンを出します。**一番下にいるときは「上へ」だけ、一番上にいるときは「下へ」だけ**を出します。途中にいるときは両方、内容が収まってスクロールできないときはどちらも出しません。端から少しの余裕の中にいれば、その端にいるものとみなします。「一番上」は、読み込み済みの履歴の先頭です。

### 一覧の項目の共通の操作

PIN・クルーステータスの履歴・検索結果の項目は、どれも次のように動きます。

- **クリック**すると、会話の該当の発言（タスクならそのカード）へスクロールして、強調します。別のミッションの項目なら、そのミッションへ切り替えてから移動します。
- 移動を始めた時点で「一番下にいる」状態を解除します。新しい発言による自動スクロールに、引き戻されないようにするためです。
- マウスを載せると、「ポップアップで表示」ボタンが出ます。押すと、その発言をポップアップで開きます。
  - タスク: 報告と指示のタブを持つポップアップ。
  - 通常の発言: 発言者・日時・本文・コピー・閉じるを持つポップアップ。
  - どちらにも「会話へ移動」ボタンがあります。
- 検索結果からポップアップを開いても、検索パレットは開いたままです。ポップアップを閉じると結果に戻ります。

### スクロールと強調

- 移動のスクロールは、遠くても短時間で終わるアニメーションです。始めは速く、終わりに向かってゆるやかになります。
- 強調は、**移動が終わってから**始め、一度光って、ゆっくり消えます。
- 利用者がスクロール・クリック・キー操作をしたら、その時点でアニメーションを止めます（強調もしません）。
- OS の「動きを減らす」設定のときは、アニメーションせず、すぐ移動します。
- 別のミッションへ切り替わる移動では、左ペインの該当のミッションの行も光らせます。ミッションの一覧が開いていて、その行が見えない位置にあるときは、見える位置へスクロールしてから光らせます。

## 上下分割

- ヘッダーのボタンで、会話を**上下に分割**できます（既定は無効）。上画面に以前の会話を出したまま、下画面で入力できます。
- 上画面は、下画面と**同じ読み込み済みの発言**を、別のスクロール領域に出します。読み込み・SSE による更新は、どちらも同じ状態から描くので、そろって変わります。
- **返答の途中（`streaming`）の発言は、上画面に出しません**（下画面だけ）。完了すると、上画面にも現れます。
- 有効にした直後と、ミッションを切り替えた直後は、上画面を直近の履歴（最下部）に合わせます。上画面にも「過去の会話を読み込む」ボタンがあります。
- [PIN・検索結果・クルーステータスの履歴・タスクのカード](#一覧の項目の共通の操作)からの移動は、分割が有効なときは**上画面**で行います。ただし、返答の途中の発言への移動は、下画面で行います。
- 上画面の高さは、全体の 1/4 が既定です。境界のドラッグで変えられます（全体の 1/10〜8/10）。
- 境界を動かしても、下画面が最下部にいたなら、最下部に居続けます。
- 一番上へ・一番下へのボタンは、上画面にも出ます（それぞれの画面の右下で、その画面だけを動かします）。

## 話し相手の選択

話し相手は、入力欄の上のバーで選びます。

### 2 つの状態

| 状態 | 意味 | 保存 |
|---|---|---|
| 基本の話し相手 | 続けて話す相手 | ミッションごとに保存 |
| 次の 1 通だけの宛先 | 次に送る 1 通だけを送る相手 | しない |

### 操作

| 操作 | 結果 |
|---|---|
| クリック／`@` の選択で Enter | 基本の話し相手を切り替える（1 通だけの宛先は取り消す） |
| Shift を押しながらクリック／`@` の選択で Shift+Enter | 次の 1 通だけの宛先にする（基本は変わらない） |
| Shift で、同じクルーをもう一度選ぶ／入力欄で Esc | 1 通だけの宛先を、送る前に取り消す |
| メッセージ・report・ボタンの定型文・すぐ送信するメニュー項目の送信 | 1 通だけの宛先を取り消し、基本に戻る（送信に失敗しても戻る） |
| ミッションの切り替え | 1 通だけの宛先を取り消す |

- 1 通だけの宛先は、基本とは別の印で示し、戻り先の基本の話し相手にも印を付けます。
- `/` のコマンド候補と、入力欄の案内は、**実際に送る相手**（1 通だけの宛先があればそちら）のものになります。
- ボタンは、ドラッグ&ドロップで並べ替えられます。並び順はブラウザに保存します。
- 幅に収まらないボタンは、右端の「»」にまとめます。押すと、残りを一覧で開きます。キーボードで「»」の中を選んでいる間は、一覧を自動で開きます。

### `@` のショートカット

- 入力欄の行頭か空白の直後で `@` を押すと、文字は入らず、ボタンの並びにフォーカスが移ります。
- ←→ で選び、Enter で決定、Esc で取り消します。どちらも、終わると入力欄に戻ります。
- メールアドレスのように、文字の直後の `@` は、そのまま文字として入ります。
- 変換中（IME）は、ショートカットの対象にしません。

## 入力欄とスラッシュコマンド

- **Ctrl+Enter** で送信します。Enter は改行です。
- 返答を待っている間も、入力はできます。送信は返答が終わるまでできません（自動では送られません）。
- 一度に動かせるターンは、ミッションごとに 1 つです。進行中に送ると、`429` が返ります（[HTTP API](http-api.ja.md#エラーコード)）。

### 過去の発言（↑ の履歴）

- **入力欄の最上行で ↑** を押すと（キャレットが先頭の行にあり、選択がないとき）、**開いているミッションの、艦長の過去の発言**を、最大20件、一覧で出します。いちばん新しいものが下（入力欄の側）で、古いものが上です。折り返した長い行の途中では、↑ はいつもどおりキャレットを上へ動かします。
- 同じ文は1回だけ出ます（最後に使ったもの）。ボタンとカスタムメニューが送る定型の発言（`report`、`engage`、`make it so`、すぐ送信するメニュー項目）は、出ません。
- 最初は、いちばん新しい発言が選ばれています。↑ で古い方へ、↓ で新しい方へ進みます（マウスを載せても選べます）。**Enter かクリックで、入力欄の中身を、その発言に入れ替え**、キャレットを末尾に置きます。**Esc**、または一覧の外のクリックで、閉じて、入力欄はそのままです。ほかのキー（文字の入力、Backspace、送信の Ctrl+Enter）でも、一覧は閉じます。返答を待っている間は、開きません。
- スラッシュコマンドの候補が開いているときは、↑ は候補のものです。一覧は、開くたびにサーバーから読み、ミッションを切り替えると閉じます。

### 入力欄の隣のボタン

左に送信ボタン（▶）があり、その右に、上から4つのボタンが並びます。

| ボタン | 動作 |
|---|---|
| そうしてくれ | 今の宛先に `make it so` を送る |
| 発進！ | `engage` を送る |
| 報告 | `report` を送る（副長（commander）や chief のクルーが、未報告のタスクをまとめる） |
| メニュー | カスタムメニューを開く |

- 上の3つは、今の宛先（1通だけの宛先があれば、そちら）に、すぐ送ります。返答の途中は、メニューのボタンを含めて、押せません。
- **カスタムメニュー**は、この艦で有効な項目を、[`quick-actions.yml`](configuration.ja.md#quick-actionsyml) の順に並べます。各項目には、名前と、その下に、送る本文が出ます。項目をクリックすると、設定に従って、本文（メッセージまたはスラッシュコマンド）をすぐ送る**か**、入力欄に入れるだけにします。入れるだけの項目には、「…」が付きます。一覧は、メニューを開くたびにサーバーから読み直します。
- 一覧の末尾の「設定…」は、**この艦の**項目の編集画面を開きます。追加、名前の変更、種類（メッセージ／スラッシュコマンド）と本文の変更、「すぐ送信」か「入力欄に入れるだけ」の選択、並べ替え、削除ができます。新しい項目は、この艦だけで有効です。他の艦も使っている項目には、その旨が出て、変更すると他の艦にも反映されます。削除は、この艦から外すだけです（「すべての艦」で有効な項目は、この艦だけを切ります。あとから作る艦には、付きます）。
- 設定アプリの「カスタムメニュー」タブでは、すべての項目と、項目ごとに有効にする艦を編集できます。

### スラッシュコマンド

プロバイダーが持つスラッシュコマンド（Claude Code の `/context`、`/compact`、`/clear`、スキルなど）を、**今の話し相手が実行できるもの**として使えます。

- 一覧は、会話用のセッションが起動するとエージェントから届きます。セッションごとに保持し、セッションが終われば消えます。タスク実行用のセッションは追跡しません。
- 本文の先頭が `/名前` で、**その名前が話し相手の一覧にある**ときだけ、コマンドとして送ります。一覧にない `/` 始まり（ファイルのパスなど）は、通常の発言です。
- コマンドは、ミッションの会話の前置き（他の参加者の発言のまとめ）を付けずに、そのまま送ります。前置きを付けると、先頭が `/` でなくなるためです。
- 結果は、通常の返信として会話に残ります。
- セッションの状態を変えるコマンド（`/clear` など）も、そのまま通します。会話の履歴とは食い違うことがあります。
- **入力欄の候補:** 先頭の `/` に続く、空白のない文字列を入力している間、候補（名前・ヒント・説明）を出します。名前の前方一致、次に部分一致の順で絞ります。↑↓で選び、Tab か Enter で `/名前 ` に補完し、Esc で閉じます（本文が変わるまで出し直しません）。一覧に合わないもの（パスなど）では出ません。
- **起動前の候補:** 一覧はセッションの起動後に届くため、プロバイダーごとに、最後に分かった一覧をデータベースに残し、起動前はそれを出します（[データモデル](data-model.ja.md#設定とキャッシュ)）。その場合は、候補の末尾に「前回の一覧」であることを注記します。そのプロバイダーでまだ一度も起動していないときは、候補の代わりに、「送信すると起動してコマンドを実行する」ことを案内します。手で打ったコマンドは、起動前の最初の 1 通でも実行されます。
- kiro は、ACP 標準の通知で届く場合のみ動作します（動作確認の範囲は README を参照）。

## クルーのステータス

### 4 つの状態

| 状態 | 意味 | 優先順位 |
|---|---|---|
| `restarting` | 艦長の操作でセッションを作り直している間 | 1（最優先） |
| `starting` | 会話用セッションの立ち上げ中（プロセスの起動から、人格などの注入が終わるまで） | 2 |
| `working` | 会話のターン中、またはタスクの実行中 | 3 |
| `idle` | それ以外 | 4 |

- 状態名は、言語設定に関わらず、英語のまま表示します（承認待ちの `approval` も同じ）。
- 起動中・再起動中の表示は、承認待ちと区別できる別の見た目にします。
- 起動中・再起動中のクルーは、再起動できません（`409`）。
- 立ち上げの段階はセッションごとの状態です。ミッションを指定した問い合わせではそのミッションのセッションを、指定なしでは全ミッションを見ます。
- **タスク実行用のセッションは使い捨てなので、`starting` として見せません。**
- プロセスが落ちたクルーは `idle` のまま表示します。次に呼ばれたとき、最初の起動と同じ経路（プロセスの起動、人格の注入、DB の会話記録からのプロンプトの再構築）で立ち上がります。処理の最中に落ちたときは、エラーのカードとして会話に出ます。サーバー自身が処理の最中に止まった場合も、次の起動のときに、「中断」のエラーとして会話に出ます（ターンは、返答の出力が始まっていたものだけ。タスクは、すべて）。それまでに書かれた本文は、カードの上に残します。記録は、ポートを確保してから行います（動いている艦を、もう一度起動しても、その艦のターンを、中断として記録しません）。
- タスクの成功・失敗は、タスク自身の属性で、クルー本人の状態ではありません。

### 更新のしかた

- ステータスは、タイムラインの更新と、起動中・再起動中が変わった合図に合わせて取り直します。**定期的な問い合わせはしません。**
- SSE を再接続したときは、会話のスナップショットと一緒に取り直します。
- リモートホストのトンネルの状態は同じ応答に載りますが、トンネルだけが変わったときは取り直しません。次の活動か画面の更新まで、古いままのことがあります。

### 行の表示

- クルーの行に、アイコン・名前・ステータス・コンテキストの使用率・未報告のタスクの件数を出します。リモートホストのクルーには、ホストの印を付けます。
- **コンテキストの使用率**は、今開いているミッションでの、そのクルーの会話用セッションの値です。セッションがなければ、空の表示にします。値は、サーバーのメモリ上にだけあり、セッションが終わると消えます。
- **未報告のタスクの件数**は、完了・失敗したが、まだ副長に報告していないタスクの数です。タスクが終わった時点で増え、report すると自動で 0 に戻ります（専用の消す操作はありません）。
- クルーの履歴（そのクルーが担当したタスクの一覧）を開けます。項目の操作は[一覧の項目の共通の操作](#一覧の項目の共通の操作)のとおりです。
- アイコンをクリックすると、[人事記録](#クルーの人事記録)を開きます。

## 承認待ち

クルーがツールの実行許可を求めている間（保留中の承認）、見逃さないよう、次の場所に表示します。

| 場所 | 表示 |
|---|---|
| 入力欄の上のトレイ | **今開いているミッションの分だけ**を出す。別のミッションの承認を、文脈なしにここで許可させないため |
| クルーの行 | 承認待ちのクルーの行を目立たせ、ステータスを `approval` にする。「クルーステータス」の見出しに件数を付ける |
| ミッションの行 | 件数を付ける。「ミッション」の見出しには、**全ミッションの合計**を出す（閉じていても気づけるように） |
| ブラウザのタブ | 全ミッションの合計が 1 件以上ある間、タイトルとアイコンで示す |

- どのミッション・どのクルーの承認待ちかは、サーバーが付けた値をそのまま使います。クライアントで、識別子の文字列を解析し直しません。
- トレイでは、許可・拒否を選べます（[HTTP API](http-api.ja.md#承認待ちpermission)）。
- ブラウザの通知（OS の通知）と通知音は、ありません。

## ミッションの一覧

- 見出しは、固定の「ミッション」です。縮めたときは、選択中の 1 件だけを表示します。
- 開くと、次のものが現れます。
  - 検索欄: スペース区切りの AND。名前に、すべての語を含むものだけに絞ります。
  - 一覧: 選択・切り替え。
  - 「アーカイブも表示」のチェック（既定はオフ）。
  - 「新しいミッション」ボタン。
- 選択や作成をしても、一覧は自動では閉じません。
- 一覧は、`missions` の自然な順序のままです。選択中のミッションを先頭に引き上げません。
- **選択中のミッションは、検索やアーカイブ非表示の絞り込みに関係なく、常に一覧に残ります。**
- 各行に、アーカイブ／復元のボタンがあります。アーカイブは削除ではなく、一覧に出すかどうかの切り替えです。**選択中のミッションは、アーカイブできません**（アーカイブ済みのものを選択中なら、復元はできます）。
- 承認待ちのある行には、件数を付けます。

## PINと古い発言への移動

- PIN は、メッセージ自身の PIN ボタンで付け外しします。一覧には、**今開いているミッションの PIN だけ**を出します。画面にない発言の PIN を外すときは、一覧から移動してから切り替えます。
- PIN は、付けた時点の発言のスナップショットです。元の発言が変わっても、PIN の内容は変わりません。

### まだ読み込んでいない古い発言へ移動する

1. 読み込み済みの履歴にあれば、そこへスクロールして強調します。
2. なければ、`GET /api/timeline/range` で、**その発言を先頭にした 1 ページ**を取り、履歴に足してから、その発言へスクロールします。
3. 足した塊と、もともとの履歴の間は、**間の発言が読み込まれていない「抜け」**になります。抜けの位置に、2 つのボタンを持つ行を出します。
   - 「続きを読み込む」: 上の塊の下端から、新しい方へ 1 ページ。
   - 「手前を読み込む」: 下の履歴の上端から、古い方へ 1 ページ。
   - 間をすべて読み終えると、行は消えて、ひと続きになります。
4. クルーの報告のカードなどのまとまりは、抜けの区間ごとに分けます。
5. ミッションを切り替えると、読み込んだ発言と抜けはすべて捨てて、直近の履歴から取り直します。SSE の再接続後は、抜けの前後の発言が隣り合ったままの抜けだけを残します。

## 検索

- ヘッダーの検索ボタン、または **Ctrl+Shift+F** で、検索パレット（画面中央のポップアップ）を開きます（開いていれば閉じます）。Esc で閉じます。閉じても、検索語・条件・結果は残ります。
- 条件が変わると、少し待ってから自動で検索します。

| 条件 | 内容 | 既定 |
|---|---|---|
| 検索語 | スペース区切りの AND（全角の空白も可） | — |
| 期間 | 開始日・終了日（ローカルの日付。終了日はその日を含む）。どちらも省略可 | 指定なし |
| 含める種類 | 艦長の発言／クルーの返信／タスクの指示と報告 | すべて |
| 対象のミッション | 個別に選べる。「すべて」もある。アーカイブ済みも、区別して選べる | 今のミッションのみ |

- 一致は、部分一致です（日本語も探せます）。大文字小文字を区別しません。`%` と `_` は、文字そのものとして探します。
- タスクは、**語ごとに、報告か指示のどちらかに含まれていれば**一致します。
- エラー・中止・システム通知は、対象外です。
- 結果は新しい順です。上限を超えたときは、切り捨てたことを示します（[HTTP API](http-api.ja.md#検索)）。各結果に、一致した前後の抜粋を、一致の範囲を強調して出します。
- 結果のまとめ方を、**ミッション別 / クルー別 / ミッション×クルー**から選べます（選んだ形は保存します）。グループの順は、そのグループで最も新しい結果の順です。クルー別では複数のミッションの結果が混ざるため、各結果にミッション名を出します。
- グループの見出しをクリックすると、折りたたみ／展開します（「すべて折りたたむ／開く」もあります）。折りたたんだグループの結果は、↑↓での選択の対象から外れます。新しい結果が届いたとき、まとめ方を変えたときは、すべて開きます。
- 結果の上部に、件数・「すべて折りたたむ／開く」・目次（グループへのリンク）を固定して出します。スクロールするのは、下の結果の一覧だけです。リンクをクリックすると、そのグループへスクロールし、折りたたまれていれば開きます。
- 結果をクリック（または ↑↓ と Enter）すると、パレットを閉じて、[会話の該当の発言へ移動](#一覧の項目の共通の操作)します。

## クルーの人事記録

クルーのアイコンをクリックすると、そのクルーの人事記録のポップアップを開きます。

- **内容:** 設定の要約（名前・ID・プロバイダー・権限モード・作業ディレクトリ・ホスト）、ペルソナ、ブリーフィング。
- **できること:** アイコンの変更、モデルの変更、セッションの再起動、ペルソナの表示。ペルソナの編集はできません（ファイルを直接編集します）。
- **ペルソナ:** 見えるのは、人格ファイル（またはプロバイダーのエージェント定義ファイル）の**中身だけ**です。プロバイダーが実際に使う最終的なプロンプト（`CLAUDE.md`、スキル、プラグイン、ユーザー設定が合わさったもの）は、取得できません。リモートホストのクルーのペルソナは、別のマシンにあるため読めません。
- **ブリーフィング:** セッション開始時に送る全文（人格・ルール・スキル・システムの案内）を、開くたびに、**送信と同じ処理で**組み立てます。すでに動いているセッションに送った内容とは、その後にファイルを編集していれば、食い違うことがあります。組み立てられないとき（ルールのファイルが読めないなど）は、空にして、理由を示します。
- **アイコン:** ラスター画像（PNG・JPEG・WebP・GIF）だけを受け付けます。**SVG は、スクリプトを含められるため受け付けません。** 形式は、拡張子や申告された種類ではなく、中身の先頭のバイトで判定します。サイズの上限があります。1 人に 1 枚で、別の形式で上げ直すと、古いファイルは消えます。アイコンがないクルーには、名前から作るアバター（頭文字と色）を出します。

## 停止と起動の見張り

プロバイダーが応答しない（ログイン切れ、ネットワークの不通、リモートホストの不調など）ときも、**ミッションが処理中のまま固まらない**ように、次の約束があります。

- **停止は、どの段階でも必ず効きます。**
  - セッションがあれば、キャンセルを送ります。
  - セッションが立ち上げ中なら、立ち上げを中断します（起動中のプロセスを止めます）。
  - どちらでも、猶予を過ぎてもターンが終わらなければ、セッションを強制終了し、待っている処理を打ち切ります。
  - 停止を要求した後の失敗（起動の中断・強制終了・プロセスの終了）は、「エラー」ではなく**「キャンセル済み」**として記録し、自動リカバリもしません。
  - 進行中のターンがなければ `409` を返します。画面は、サーバーの状態を取り直して合わせます。
  - 画面では、停止を押すと停止ボタンが「停止中」の表示になり、押せなくなります。ターンが終われば戻ります。
- **セッションの立ち上げには、上限があります。** 超えたら、起動中のプロセスを止めて、「起動がタイムアウトした」という失敗にします（ミッションは解放されます）。遅れて終わった立ち上げは、セッションとして登録せず、クライアントを止めます。タスクの実行の起動にも、同じ上限が効きます。
- **人格などを送るブリーフィングへの応答が長く無いときは、起動の失敗にします。** それ以外のブリーフィング送信の失敗は、警告だけで続けます。
- **ターンの途中で、長く何の活動もないときは、ハングとして扱い、自動リカバリを試みます。** ただし、**承認要求に艦長が答えるのを待っている間は、ハングとして扱いません**（席を離れていても、時間切れになりません。答えると、再開します）。クルータスクも同じで、ハングしたタスクのセッションは捨てます（次のタスクは、新しいセッションで始まります）。

これらの時間は、コードの定数です（設定ファイルでは変えられません）。

## 使用量の表示

- 返答・タスクのカードに、そのターンの消費量を表示します。単位はプロバイダーで異なります。
  - claude: 推定費用（USD）。ACP の使用量通知の累積値から、**ターン開始時点との差分**を計算します。実際の請求額ではありません。
  - kiro: 独自のクレジット。
- **アカウント**の区画に、認証しているアカウントごとの使用率と、そのアカウントで動くクルーを出します。
  - 使用率の枠は、クルー単位でもプロバイダー単位でもなく、アカウント単位で決まります。サーバーが組んだものを、そのまま並べます。
  - ローカルのクルーは、プロバイダーごとにまとめます。claude は `claude auth status` で、アカウント（組織を含む）を識別します。
  - 識別できないもの（kiro、API キー認証、未ログイン）は、推測で束ねず、「アカウント不明」の枠にします。
  - リモートホストのクルーは、別のマシンの別のログインで動くため、集計しません。「集計対象外」の枠に出します。
  - 取得には、一定の間隔の制限とキャッシュがあります。更新ボタンと、SSE の接続時に、取り直します。
  - **メールアドレスは、画面にそのまま出ます**（自分のマシンで動かす、自分用の画面のためです）。
