## 設定の構成

| ファイル | 場所 | 範囲 | 内容 |
|---|---|---|---|
| `config.yml` | `~/.make-it-so/`（任意） | 全艦に共通 | 言語、プロバイダーの起動コマンド、ログ |
| `roster.yml` | `~/.make-it-so/` | 艦隊（全艦に共通） | クルーの名簿（ID・表示名・プロバイダーなど） |
| `hosts.yml` | `~/.make-it-so/` | 艦隊 | リモートホストの宛先（任意） |
| `quick-actions.yml` | `~/.make-it-so/` | 艦隊（項目ごとに艦を指定） | 入力欄のカスタムメニュー（任意） |
| `ship.yml` | `~/.make-it-so/ships/{艦ID}/` | 艦ごと | ポート、艦の名前、役職の配属、ルール、作業ディレクトリ |

いずれも YAML です。必須の設定が欠けている場合は、既定値に黙って置き換えず、起動時にエラーで止まります（[起動時の検証とエラー](#起動時の検証とエラー)）。

## 設定ファイルの場所

設定は、すべてホームディレクトリの `~/.make-it-so/` にあります（艦隊そのものです。[ディレクトリ配置](#ディレクトリ配置)）。場所は固定で、変える設定も環境変数もありません。

- `config.yml` は、**無くても動きます**（既定値を使います）。
- 艦（`~/.make-it-so/ships/{艦ID}/ship.yml`）と、名簿（`roster.yml`）は必須です。無ければ、起動時にエラーで止まります。
- 場所を変えたいとき（開発・テスト）は、`HOME` を差し替えて起動します。

## 起動の引数

| 引数 | 内容 |
|---|---|
| `--ship <艦ID>` | 起動する艦（`~/.make-it-so/ships/` 下のディレクトリ名）。`--ship=<艦ID>` でも可。艦が1つなら省略できる。複数あって省略すると、候補を示してエラー |
| `--settings` | 艦の代わりに、**設定サーバー**を起動する。`~/.make-it-so/` の中身を、ブラウザで編集する。`--ship` とは同時に指定できない |
| `--all` | `~/.make-it-so/ships/` の艦のうち、**動いていないものをすべて**、それぞれ独立したプロセスとして起動して、終了する（動いている艦はそのまま）。艦ごとの結果（`started` / `running` / `conflict` / `no_port`）を表示し、ポートを別のものが使っている艦（`conflict`）などがあれば、終了コードは 1。`--ship`・`--settings` とは同時に指定できない |
| `--port <数>` | `--settings` のときの、設定サーバーのポート（既定 `3938`）。`--settings` なしでは指定できない（艦のポートは `ship.yml`） |

- 例: `npm start -- --ship alpha`、`npm run dev -- --ship alpha`、`npm start -- --settings`。
- 設定サーバーは、認証がないため、`127.0.0.1` だけで待ち受けます（変える設定はありません）。
- 設定は、ファイル（`config.yml`・`ship.yml` など）と、この引数だけで決まります。**サーバーが読む環境変数は、ありません**（艦のポートやルートを環境変数で上書きすると、艦ごとのデータの分離を、誤って崩しうるため）。
- ビルド時の環境変数 `VITE_API_BASE`（クライアントの接続先）は、**使えません**。サーバーが、別のオリジンからの呼び出しを拒否するためです（[セキュリティ](../security.ja.md)）。画面は、常に、同じオリジンのサーバーに接続します。

## 設定画面（`--settings`）

`npm start -- --settings` で、設定サーバー（既定 `http://127.0.0.1:3938`）が起動し、`~/.make-it-so/` の中身をブラウザで編集できます。

| タブ | できること |
|---|---|
| 概要 | ディレクトリの有無、各ファイルの有無、人格の数、艦の一覧（読み取りのみ） |
| Config | [下の表](#configyml)の全項目を、フォームで編集する |
| リモートホスト | `hosts.yml` のホストの追加・変更・削除 |
| カスタムメニュー | `quick-actions.yml` の項目の編集と、項目ごとに有効にする艦の選択 |
| 名簿 | `roster.yml` のメンバーの追加・変更・削除、人格（`personnel/{ID}.md`）の編集、アイコンのアップロード |
| 艦 | 艦の追加（最小の艦: 副長の役職 1 つ）と、`ship.yml` の編集（ポート・名前・作業ディレクトリ・ルール・スキル・ターゲット・役職の配属）。艦の**起動・停止**と、状態の表示 |
| プロジェクトから | 既存のプロジェクトを読み取って、名簿と艦の下書きを作り、確認してから保存する([下](#既存のプロジェクトから艦を作る)) |

- 設定画面の言語は、ヘッダーの「EN | 日本語」で切り替えます。選んだ言語は**このブラウザにだけ**保存し、艦のDBにも `config.yml` にも書きません。まだ選んでいないときは、`config.yml` の `language` に従います（未設定なら英語）。
- 保存は、**変えた項目だけ**を書き換えます。コメントと、キーの順序、知らないキーは、そのまま残ります。保存の前のファイルは、`.bak`（1世代）に残します。
- 既定値と同じ値にした項目は、ファイルから**消します**（ファイルを短く保つため）。
- 入力に誤りがあるときは、何も書かずに、項目ごとにエラーを返します。ファイルが YAML として読めないときは、上書きせず、そのことを知らせます。
- 艦が使っているホストは、削除も名前の変更もできません。
- 艦の保存は、**起動時と同じ検証**を通します（ポートの重複、存在しないファイル・ディレクトリ、`commander` が 2 人、未定義のホストやメンバー、リモートのクルーの `cwd`・`access` など）。誤りは項目ごとに示し、何も書きません。艦のターゲットのパスは、存在するディレクトリであること。
- **艦の削除:** 艦の画面の最下部の「この艦を削除」で、艦のディレクトリごと（設定・DB・ログなど、艦が持っていたものすべて）を消します。**元には戻せません。** 動いている艦は削除できず（先に停止する）、確認のために、艦のIDの入力が要ります。名簿のメンバーは残ります。 `ship.yml` を読めない艦は、動いているかを確かめられないので、画面からは削除できません（ファイルを直すか、ディレクトリを手で消します）。
- **艦の起動・停止:** 設定サーバーが、艦を、独立したプロセスとして起動します（設定サーバーと同じ実行方法で、`--ship` を付けます）。**設定サーバーを閉じても、艦は動き続けます。** 動いているかどうかは、艦のポートの `GET /api/health`（`shipId` と `pid` を返す）で調べます。そのため、手で起動した艦も、見つけて停止できます。停止は、その `pid` へ `SIGTERM` を送ります。ポートを別のものが使っているときは、起動も停止もしません。起動した艦の出力は、`ships/{艦ID}/logs/stdout.log` に残ります（画面で見られます）。
- 艦が配属しているメンバーは、削除できません。メンバーを削除しても、人格とアイコンのファイルは残ります。IDは、作った後は変えられません（ファイル名になるため）。
- ルール・スキルのファイルは、起動時と同じく、存在するファイルだけを受け付けます。人格を空にして保存すると、ファイルを消します（元のファイルは `.bak` に残ります）。
- 艦には、**次に起動したときに**反映されます（動いている艦は、再起動が要ります）。

### 既存のプロジェクトから艦を作る

「プロジェクトから」タブは、すでにエージェントの設定があるプロジェクトのディレクトリを指定すると、そこから名簿と艦の下書きを作ります。`~/.make-it-so/` がまだ無くても使えます（保存のときに作ります）。すでに使っている場合は、別のプロジェクトを、新しい艦として足す用途になります。

読み取るもの:

| プロバイダー | エージェント定義 | モデル・権限モード | ルールの候補 | MCP（報告のみ） |
|---|---|---|---|---|
| claude | `.claude/agents/*.md`（frontmatter の `name`。無ければファイル名） | `.claude/settings.json` と `settings.local.json`（後者が優先）の `model`、`permissions.defaultMode` | `CLAUDE.md` | `.mcp.json` |
| kiro | `.kiro/agents/*.json` と `*.md`（`name`。無ければファイル名） | エージェント定義の `model` | `.kiro/steering/*.md` | `.kiro/settings/mcp.json` |

kiro の読み取りは、仕様に沿って作ったもので、実機での動作確認は未実施です。

下書きの内容:

- **エージェント定義1つにつき、名簿の1人。** 定義が1つも無いときは、汎用の1人（`lead`）にします。
- **エージェント定義は、コピーしません。** 役職の `agent` で名前を参照し、作業ディレクトリ（`cwd`）はプロジェクトにします。定義を編集すれば、元のプロジェクトのままで反映されます。
- **全員が `chief`。** commander が要るときは、画面で1人選びます。
- **艦のIDと名前は、プロジェクトのフォルダ名から。** ポートは、他の艦が使っていない番号（3939 から）にします。プロジェクトは `targets` に入り、全員が `readwrite` で担当します。
- **名簿に同じIDのメンバーが既にいる**（プロバイダーも同じ）ときは、既存のメンバーを使う形が初期値です。プロバイダーが違うときは、別のIDにします。
- **`.mcp.json` などのMCPは、取り込みません。** クルーにできることが広がるので、見つかったことを知らせるだけです。
- **`bypassPermissions`（確認をすべて省く権限モード）は、取り込みません。** 知らせるだけです。
- **ルールの候補は、初期状態では艦に加えません。** プロバイダーが自分で読むファイルなので、二重に渡さないためです。必要なら、画面で選びます。

保存は、名簿の新しいメンバーと艦を、まとめて1回で行います。どれか1つでも検証を通らなければ、名簿を元の内容（ファイルが無かったなら、無い状態）に戻して、何も残しません。

## `config.yml`

make-it-so 本体の共通設定です。雛形は、リポジトリの [`config.sample.yml`](../../config.sample.yml) にあります。

| キー | 型 | 既定 | 内容 |
|---|---|---|---|
| `language` | `en` \| `ja` | `en` | UIの言語。画面から変えた値は艦のDBに保存され、こちらより優先される |
| `crew_language` | `en` \| `ja` | `language` と同じ | クルーが話す言語。画面から変えた値はDBに保存され、こちらより優先される |
| `theme` | `classic` \| `light` \| `dark` | `classic` | 画面の既定の見た目。左ペインの「設定」区画（デスクトップアプリでは表示メニュー）で選んだ値は、そのブラウザに保存され、こちらより優先される |
| `acp.provider` | `kiro` \| `claude` | `claude` | `roster.yml` でプロバイダーを指定していないクルーに使う、既定のプロバイダー |
| `acp.kiro.command` | 文字列 | `kiro-cli` | kiro の起動コマンド |
| `acp.kiro.args` | 文字列の配列 | `["acp"]` | kiro の起動引数 |
| `acp.claude.command` | 文字列 | `npx` | claude の起動コマンド |
| `acp.claude.args` | 文字列の配列 | `["--yes", "@agentclientprotocol/claude-agent-acp@0.106.0"]` | claude の起動引数（アダプターの版を固定している） |
| `server.host` | 文字列 | `127.0.0.1` | 待ち受けるホスト。認証がないため、変更は [安全上の注意](../security.ja.md) を理解した上で。**IP アドレスか `localhost` で、アクセスしてください**（それ以外の名前の `Host` は、`403` になります。名前を使いたい場合は、v0.1 では未対応です） |
| `debug` | 真偽値 | `false` | デバッグ用のルート（`POST /api/debug/simulate-error`）を有効にする |
| `logging.level` | `debug` \| `info` \| `warn` \| `error` | `info` | このレベル未満のログは、コンソールにもファイルにも出さない |
| `logging.maxFileSizeMb` | 数値 | `5` | ログファイルの上限。超えると `app.log` を `app.log.1` へ退避する（1世代だけ保持） |

- `init` が作る `config.yml` には、`language`・`acp.provider` が入ります。
- 未対応の `language` / `crew_language` / `theme` の値は、エラーになります。

## `roster.yml`

艦隊のクルーの名簿です。キー（メンバーID）が、人格ファイル・アイコンの名前になります。

```yaml
crew:
  alex:
    name: "Alex"
    provider: "claude"
  sam:
    name: "Sam"
    provider: "claude"
    model: "sonnet"          # model は、claude のクルーにだけ効きます（kiro では、モデルを変えられません）
    rules: [personnel/sam-rules.md]
```

| キー（`crew.<ID>.`） | 型 | 既定 | 内容 |
|---|---|---|---|
| `name` | 文字列 | **必須** | UIに出す表示名 |
| `provider` | `kiro` \| `claude` | `acp.provider` | このメンバーのプロバイダー。**プロバイダーの指定は、ここだけ**（`ship.yml` では上書きできない） |
| `model` | 文字列 | 指定なし | このメンバーの既定のモデル（ACP のモデル選択肢の値。例: `opus`、`sonnet`）。`ship.yml` の指定が優先 |
| `permission_mode` | 文字列 | 指定なし | 権限モード。`ship.yml` の指定が優先 |
| `rules` | 文字列の配列 | なし | このメンバーに紐づくルールのファイル（`~/.make-it-so` 基準の相対パス）。どの艦に配属されても有効 |
| `skills` | 文字列の配列 | なし | このメンバーに紐づくスキルのファイル（`~/.make-it-so` 基準） |

- メンバーIDは、`[A-Za-z0-9]` で始まり、英数字・`_`・`-` だけで書きます（人格ファイルとアイコンの名前になるため）。

## `ship.yml`

艦ごとの設定です。1つのディレクトリ（`~/.make-it-so/ships/{艦ID}/`）が1つの艦で、`ship.yml` を持つディレクトリだけが艦として扱われます。

```yaml
port: 3939
name: "My Ship"
rules: [rules/working-agreement.md]
targets:
  app: /path/to/your/project
crew:
  first_officer:
    member: alex
    rank: commander
  chief_engineer:
    member: sam
    rank: chief
    access:
      app: readwrite
  ensign:
    member: jo
    permission_mode: default
```

### 艦の設定

| キー | 型 | 既定 | 内容 |
|---|---|---|---|
| `port` | 整数 | **必須** | この艦のHTTPポート。**艦ごとに異なる値**にする（重複は起動時にエラー） |
| `name` | 文字列 | 艦のID | UIに出す艦の名前 |
| `cwd` | 文字列 | 艦のルート | 艦単位の作業ディレクトリ（相対パスは艦のルート基準。存在するディレクトリであること） |
| `rules` | 文字列の配列 | なし | 艦内の全クルーに、全文を注入するルールのファイル（艦のルート基準） |
| `skills` | 文字列の配列 | なし | 艦内の全クルーに案内するスキルのファイル（艦のルート基準） |
| `targets` | `名前: パス` の対応 | なし | 艦が担当するディレクトリの名前付き集合。クルーの `access` で参照する |
| `crew` | 役職名 → 配属 | **必須（1人以上）** | 役職の定義。役職名は、英数字・`_`・`-`（先頭は英数字）で、それ以外は自由 |

### 役職の配属（`crew.<役職名>.`）

| キー | 型 | 既定 | 内容 |
|---|---|---|---|
| `member` | 文字列 | **必須** | `roster.yml` のメンバーID。名簿に無い場合は、**エラーで起動を止める**（綴りの間違いで、役職が黙って消えないように） |
| `rank` | `commander` \| `chief` \| `crew` | `crew` | 階級。タスクに関する権限を決める（下表）。`commander` は艦に1人まで |
| `model` | 文字列 | 名簿の値 | この役職で使うモデル（名簿の指定より優先） |
| `permission_mode` | 文字列 | 名簿の値 | 権限モード（名簿の指定より優先） |
| `cwd` | 文字列 | 艦の `cwd` | このクルーの作業ディレクトリ。人格の出どころとは独立 |
| `agent` | 文字列 | なし | プロバイダー側の agent 定義の名前。指定すると、その定義が人格になり、`personnel/{ID}.md` は注入しない |
| `access` | `target名: readonly \| readwrite` | なし | `targets` のうち、どこをどの権限で担当するか。書かれない target は担当範囲外 |
| `host` | 文字列 | なし | `hosts.yml` のホスト名。指定すると、そのクルーはリモートホストで動く。`cwd` が必須 |

階級:

| 階級 | タスクの発行（`dispatch_task`） | 報告（`list_unreported_tasks`）で扱えるタスク |
|---|---|---|
| `commander` | できる | 艦の**すべて** |
| `chief` | できる | **自分が発行した**もの |
| `crew` | できない（サーバーが拒否する） | 見えない |

- 艦長が最初に話しかける既定の相手は、`commander` のクルーです。いなければ、`crew:` に最初に書いたクルーです。
- 権限モード（`permission_mode`）は、セッション作成直後にプロバイダーの設定として適用します。claude の値は `default`（毎回確認）・`acceptEdits`・`plan`・`auto`・`bypassPermissions`。選べない値、または対応しないプロバイダー（kiro）では、警告を出して既定のまま動きます。
- 旧名の `profile` が書かれていると、`agent` への改名を促すエラーで止まります。
- `access` を使う `targets` は、**プロンプトでの取り決めです**（技術的なアクセス制御ではありません）。詳細は [安全上の注意](../security.ja.md) を参照してください。
- リモートホストのクルー（`host` あり）は、`access` を指定できません（エラー）。`skills` は、名前と説明だけを案内し、クルーは、本文を `get_skill` ツールで読みます。

## `hosts.yml`

リモートホストの宛先の対応表です（任意）。

```yaml
hosts:
  dev-server:
    destination: dev-server   # ~/.ssh/config の Host 名、または user@host
```

| キー | 型 | 内容 |
|---|---|---|
| `hosts.<名前>.destination` | 文字列 | `~/.ssh/config` の Host 名、または `user@host`。空文字・空白を含む値・`-` で始まる値（ssh のオプション注入）は拒否する |

- 書けるキーは `destination` だけです。鍵のパス・ポート・ユーザー・ホスト鍵の扱いなど、接続の詳細は、各PCの `~/.ssh/config` に書きます。未知のキーは、移し先を示すエラーになります。
- `hosts.yml` が無い場合、リモートのクルーは使えません（`ship.yml` が `host:` を参照していればエラー）。

## `quick-actions.yml`

入力欄のカスタムメニュー（よく使うメッセージとスラッシュコマンド）です（任意）。1つのファイルに、すべての艦の項目を置き、項目ごとに、有効にする艦を指定します。各艦も、メニューボタンから、その艦の項目を編集できます（[カスタムメニューを使う](../guides/use-custom-menu.ja.md)）。

```yaml
actions:
  - id: review
    name: Review the diff
    kind: message
    command: Please review the current diff and list any risks.
    send: fill
    ships: [my-ship]
  - id: compact
    name: Compact
    kind: slash
    command: /compact
    send: now
    ships: all
```

| キー | 型 | 説明 |
|---|---|---|
| `actions[].id` | 文字列 | 項目のID（英数字で始まり、英数字と `.` `_` `-`、64文字まで）。画面で追加した項目には、`qa-` と16進8桁が付く |
| `actions[].name` | 文字列 | メニューに出す名前（1〜40文字） |
| `actions[].kind` | `message` / `slash` | `message` は、本文をメッセージとして送る。`slash` は、スラッシュコマンドを実行する。`/` で始まる1行（`/` がなければ補う） |
| `actions[].command` | 文字列 | 送る文字列（4000文字まで） |
| `actions[].send` | `now` / `fill` | `now` は、クリックですぐ送る（既定）。`fill` は、入力欄に入れるだけで、送る前に直せる |
| `actions[].ships` | `all` か艦IDの一覧 | 項目を有効にする艦。`all` は、あとから作った艦も含む |
| `actions[].except` | 艦IDの一覧 | `ships: all` のとき、項目を切る艦。「すべての艦」で有効な項目を、ある艦が外したときに書かれる。一覧の指定では、無視される |

- 項目は50個まで。メニューには、ファイルの順に出ます。
- `quick-actions.yml` がなければ、どの艦にも `Resume`（`/resume`）と `Compact`（`/compact`）が出ます。ファイルは、最初に保存したときに作られます。
- 正しい `id`・`name`・`command` が無い項目と、未知の `kind` の項目は、読み飛ばします。`ships` が無い項目は、どの艦でも無効です。先頭の `/` を省いて書いた `slash` の項目は、`/` を補って読みます。YAML として読めないファイルは、上書きせず、メニューと設定画面がそれを知らせます。

## 人格ファイル・アイコン

人格とアイコンは、艦隊の `personnel/` に、メンバーIDを名前にして置きます。

| ファイル | 内容 |
|---|---|
| `~/.make-it-so/personnel/{ID}.md` | 人格（クルーの口調・性格などのプロンプト）。起動時に注入する。無ければ人格なし。`agent` を指定したクルーには注入しない |
| `~/.make-it-so/personnel/{ID}.{png\|jpg\|webp\|gif}` | アイコン。手で置いても、画面からアップロードしても同じ。1人に1枚、1MBまで。SVG は受け付けない。画像の形式は、拡張子ではなく中身の先頭のバイトで判定する |

## ルール・スキルのファイル

- **ルール:** 起動時に、全文を注入する Markdown のファイル。名簿のメンバーごと（`~/.make-it-so` 基準）と、`ship.yml`（艦のルート基準）の両方に書け、個人 → 艦の順に連結する。存在しないファイルは、起動時にエラー。
- **スキル:** 一覧（名前と説明）だけを案内し、本文は、必要なときにモデルが自分で読む（ファイル名は `skill.md`（小文字）。Claude Code の `SKILL.md` をそのままコピーしても、拾われません）。先頭の YAML frontmatter に `name` と `description` が必要で、無い・不正なファイルは警告して除外する。艦の `skills/*/skill.md` は自動で走査し、名簿・`ship.yml` の `skills:` で明示したものを後ろに並べる（同名は先に出たものが優先）。リモートホストのクルーは、これらのファイルを読めないので、名前と説明だけを案内し、本文は `get_skill` ツールで読む（そのクルーに案内したスキルだけを返す）。

## ディレクトリ配置

```
~/.make-it-so/
  roster.yml
  hosts.yml                  # 任意
  quick-actions.yml          # 任意
  personnel/
    {ID}.md                  # 人格
    {ID}.png                 # アイコン（任意）
  ships/
    {艦ID}/
      ship.yml
      rules/ skills/         # 任意。ship.yml から参照するファイル、艦のスキル（skills/*/skill.md）
      report-format.md       # 任意。report の書式。無ければ既定の書式を使う
      workspace/             # クルーの自由な作業場所（クルーに案内する）
      data/bridge.db         # 艦のDB（SQLite）
      logs/app.log           # ログ
      turns/                 # 実行中のターンの作業領域（一時ファイル）
      agents/{agent}/results/ # 実行中のクルータスクの作業領域（一時ファイル）
```

- `data/`・`logs/`・`turns/`・`agents/` は、make-it-so が必要に応じて作ります。
- `turns/` と `agents/` の中身は、ストリーミング中の本文を置く一時ファイルで、確定すると DB に書いて消します。
- DB を更新する前に、`data/bridge.db.bak-v<旧版>` へコピーを残します（[データモデル](data-model.ja.md) を参照）。

## 起動時の検証とエラー

次の場合は、既定値に置き換えず、メッセージを出して起動を止めます。

| 条件 | 内容 |
|---|---|
| `~/.make-it-so/ships/` が無い、または艦が1つも無い | `npm run init` で作るか、`ship.yml` を持つディレクトリを置く |
| 艦が複数あり `--ship` が無い | 候補を示す |
| `--ship` の艦が見つからない | 候補を示す |
| `port` が無い、整数でない、1〜65535 の範囲外、または艦同士で重複 | 艦ごとに異なる `port` が必須 |
| `roster.yml` が無い、または `crew:` が無い | 名簿は必須 |
| `ship.yml` に `crew:` が無い、または役職が1つも読み込めない | 1人以上が必要 |
| `rank` が `commander`・`chief`・`crew` 以外 | — |
| 役職名が、英数字・`_`・`-`（先頭は英数字）以外を含む。役職の中身が `member` を持つ対応でない | タスクのIDやディレクトリ名に使うため |
| `commander` が2人以上 | 艦に1人まで |
| `cwd` が存在しない（またはディレクトリでない） | ローカルのクルー。リモートのクルーは、絶対パスであることだけを検査する |
| `host` のクルーに `cwd` が無い、または絶対パスでない | リモートは `cwd` が必須 |
| `host` が `hosts.yml` に無い | 定義済みのホスト名を示す |
| `host` のクルーに `access` がある | 未対応 |
| ルール・スキルのファイルが無い | 存在確認を行う |
| `hosts.yml` に `destination` 以外のキー、または不正な `destination` | — |
| YAML が壊れている | どのファイルかを、行・列つきで示す |
| `language` / `crew_language` が未対応の値 | `en`・`ja` のみ |
| 使われているメンバーの `name` が無い・空、メンバーIDが形式（英数字・`_`・`-`）に合わない | — |
| 役職の `access` の値が `readonly`・`readwrite` 以外 | — |
| `acp.provider`・名簿の `provider` が `kiro`・`claude` 以外（綴りの間違いなど） | — |
| `ship.yml` の役職が、名簿に無いメンバーを指している | 名簿のメンバー一覧を示す |
| `debug` が真偽値でない、`logging.level` が未対応、`logging.maxFileSizeMb` が正の数でない | — |
| `acp.*.command` が空・文字でない、`acp.*.args` が文字の配列でない、`server.host` が空 | — |
| `profile` を使っている | `agent` に改名する |
