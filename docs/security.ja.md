# セキュリティ

make-it-so は、AI エージェントに、コマンドの実行とファイルの書き込みをさせるツールです。この文書は、何を信頼しているか、何を守っていないか、利用者が何に気をつけるかを説明します。

## 前提

- **自分のマシンで、自分だけが使う**ことを前提にしています。複数人で使う、ネットワークに公開する、**他のユーザーがいる共有マシンで使う**使い方は、想定していません（`127.0.0.1` は、同じマシンの他のユーザーからも届きます）。
- クルー（AI エージェント）は、**あなたのユーザーの権限**で動きます。make-it-so は、その権限を制限するものではありません。

## 信頼の境界

```
 ブラウザ ──HTTP──▶ サーバー ──標準入出力──▶ エージェント（クルー）
 （艦長）            127.0.0.1                   あなたの権限で動く
                      │ SSH
                      ▼
               リモートホストのエージェント
```

| 境界 | 信頼のしかた |
|---|---|
| ブラウザ → サーバー | **認証なし。** 待ち受けているホストに届く人は、艦長として操作できる。ブラウザからの呼び出しは、`Host` と `Origin` の検査で、同じオリジンのページだけに絞る（下記） |
| ブラウザ → 設定サーバー（`--settings`、既定 3938） | **認証なし。** 艦の起動・停止・**削除**、`config.yml` の書き換え（**エージェントを起動するコマンドの変更を含む**）、任意のディレクトリの読み取り（「プロジェクトから」）ができる。艦のサーバーと同じ信頼境界で、同じ検査を行う |
| サーバー → エージェント | エージェントは、艦長の指示と、他のクルーのタスクの指示に従って動く。権限はプロバイダーの権限モードに従う |
| エージェント → 掲示板（`/mcp`） | UI のポートとは別の、専用のリスナー（`server.host` ではなく `127.0.0.1` 固定で、ポートは OS が選ぶ）。起動のたびに作る秘密の値（`x-makeitso-token`）。このサーバーが起動したセッションにだけ渡し、ない呼び出しは `401` で断る。識別ヘッダーで、呼び出し元の役職とミッションを判別するが、**呼び出し元ごとの認証ではない** |
| サーバー → リモートホスト | SSH（利用者の `~/.ssh/config` と鍵）。接続の詳細は、make-it-so の設定ファイルに持たない |
| サーバー → プロバイダー | 会話の内容が、プロバイダー（Anthropic、kiro）へ送られる |

## 守っていないこと

次は、**意図して守っていない**、または**技術的な強制力を持たない**ものです。

- **認証・認可がありません。** `server.host` を `127.0.0.1` 以外（`0.0.0.0` など）にすると、ネットワーク上の誰でも、クルーへ指示を出せます。クルーはファイルを書き込めます。信頼できるネットワークの外へ、公開しないでください。
- **同じマシンの、他のユーザーや他のプロセスからの呼び出しは、防げません。** `Host`・`Origin` の検査が防ぐのは、**ブラウザで開いた Web ページ**からの攻撃だけです。
- **エージェントは、自分の承認要求に、自分で答えられます。** 承認の API（`/api/permissions/…/respond`）にも認証がなく、エージェントが実行できるコマンド（`curl` など）で、呼べるためです。リポジトリのファイルなどに仕込まれた指示（プロンプトインジェクション）で、承認を飛ばされる可能性があります。`permission_mode: default` は、**確認を求める画面を出すだけ**で、悪意のあるエージェントを止めるものではありません。
- **`/mcp` は、秘密の値を持つプロセスなら、`commander` として、タスクを委任できます。** 秘密の値はどのファイルにも書きませんが、エージェントのプロセスに渡す MCP の設定に入っています。同じマシンで、それを読めるプロセス（たとえば、エージェント自身が実行するコマンド）は、使えます。秘密の値と識別のヘッダーがあれば、クルーへの指示（プロンプトの実行）になります。
- **ルール・スキルのファイル（`rules`・`skills`）は、絶対パスや `../` も指せます。** あなたが読めるファイルは、何でも、クルーのプロンプトに入り、プロバイダーへ送られます。設定を書くのは、あなたなので、想定内ですが、他人の設定ファイルを、そのまま使わないでください。案内したスキルの本文は、`/mcp` の `get_skill` を通して、リモートホストのクルーにも届くので、リモートのホストとそのプロバイダーにも送られます。このツールは、そのクルーに案内したスキルだけを返しますが、`/mcp` の他の部分と同じ識別ヘッダーに頼っているので、上と同じ注意が当てはまります。
- **使用量の表示は、`PATH` 上の `claude`・`kiro-cli` を実行します**（`acp.*.command` の設定とは別です）。
- **ブラウザの画面では、エージェントの出力の中のリンクを、新しいタブで開けます。** 宛先は、エージェントが書いたものです。クリックする前に、宛先を確かめてください。
- **カスタムメニュー（`~/.make-it-so/quick-actions.yml`）は、ローカルのどのプロセス（クルーを含む）からも、書き換えられます。** 項目の名前と、送る本文は別で、「すぐ送信」の項目は、クリックすると、艦長自身の発言として送られます。メニューには、名前の下に、本文が出ます。クリックする前に、読んでください。ほかの設定ファイル（`config.yml`、人格、ルール）も、同じです。
- **クルーの権限を決めるのは、あなたです。** 信頼できないリポジトリを、クルーの `cwd` や `targets` にしないでください。
- **`claude-agent-acp` は、起動のたびに `npx --yes` で取得します。** 版は固定していますが、内容のハッシュは固定していません。取得したコードは、あなたの権限で実行されます。npm のレジストリを信頼する前提です。
- **担当範囲（`targets`・`access`）は、プロンプトでの取り決めです。** 「このディレクトリ以外は禁止」という案内を、クルーに送るだけです。**技術的なアクセス制御ではありません。** クルーは、`cwd` の外のファイルにも、届きえます。プロバイダー固有の権限の仕組みには、個別に対応しない方針だからです。
- **クルーの権限は、プロバイダーの権限モードに任されています。** claude で、権限モードを指定しないときの既定（`auto`）は、`touch` のような状態を変えるコマンドも、承認なしで通します。確認を求めたいクルーには、`permission_mode: default` を指定します（[権限モードを変える](guides/change-permission-mode.ja.md)）。`default` でも、プロバイダーの許可リストにあるツールは、確認されません。
- **掲示板（`/mcp`）を守るのは、その秘密の値だけです。** リモートホストのクルーは、逆トンネルを通じて、リモートの `127.0.0.1` から掲示板に届き、秘密の値は、そこで動くエージェントのプロセスに渡されます。**そのホストを共有する他のユーザーも、それを読めれば、掲示板を呼べます。** 信頼できるホストだけで使ってください。
- **会話の内容は、すべて手元の DB（`{艦}/data/bridge.db`）に、平文で保存されます。** 暗号化はしていません。
- **メールアドレスなどのアカウント情報は、画面にそのまま表示されます。**
- **クルーが `render_ui` で出すフォームは、クルーが作ります。** ボタンに見えるラベルと、押したときに送られる内容は別です。操作名と値は、クルーが決めます。艦長は、送られた文面を見られません。リポジトリに仕込まれた指示に従ったクルーが、紛らわしいフォームを出す可能性があります。答える前に、フォームが何を聞いているかを読んでください。
- **`POST /api/a2ui/:itemId/answer` と `/dismiss` に、認証がありません。** クルーは、`curl` などのコマンドで、自分のフォームに答えたり閉じたりできます（承認要求に、自分で答えられるのと同じです）。そのとき書いたコメントは、艦長のコメントとして表示されます。
- **フォームの文中のリンクの行き先は、クルーが決めます。** 新しいタブで開きます。基本カタログの `openUrl` 関数は、`http`・`https`・`mailto`・`tel` だけを、クリックされたときにだけ開きます。
- **フォームの中の画像は、`data:` 形式も含めて表示されます。** 外部からの読み込みは、`Content-Security-Policy` だけで止めています。フォームが、画像で別のものに見せかけることはできます。
- **A2UI のライブラリが、既知の脆弱性情報（advisory）を持ち込みます。** `@a2ui/react` と `@a2ui/web_core` は、それぞれ `zod` 3 を内側に持っています（非常に大きな集合を検証するときに、メモリを使い果たすという情報）。サーバーは、これでフォームを検証します。リクエストのボディは 1 MB に制限していて、`/mcp` に届くのは、ローカルの呼び出し元だけです。

## 守っていること

- **既定は、このマシンだけ（`127.0.0.1`）で待ち受けます。**
- **ブラウザからの呼び出しを、同じオリジンのページだけに絞ります。**
  - `Host` ヘッダーが、IP アドレスか `localhost` でなければ、`403` にします（悪意のある Web ページが、自分のドメインを `127.0.0.1` に向けて、同じオリジンを装う **DNS リバインディング** への対策）。
  - `Origin` ヘッダーがあり、サーバー自身のオリジンと違えば、`403` にします（他のサイトからの、本文のない `POST` なども含めた、**クロスサイトの呼び出し** への対策）。
  - `Sec-Fetch-Site` が `same-origin`・`none` 以外（`cross-site`・`same-site`）の呼び出しも、`403` にします。`<img>` や `<script>` のタグは、`Origin` を付けずに、GET を送れるためです（応答は、ページからは読めませんが、GET で起きる副作用を避けます）。
  - `Origin` のない呼び出し（`curl`、エージェント、CLI）は、ブラウザのページではないので、通します。
  - CORS は許可しません。画面は、同じオリジンの相対パス（`/api`）でだけ呼びます。
  - 制約: `server.host` を `localhost` や IP アドレス以外の**名前**で使うと、この検査で拒否されます（v0.1 では、名前での公開に未対応です）。
- **画面に、外部の画像を読み込ませません。** エージェントの出力（Markdown）の画像は、表示せず、代替テキストだけを出します（画像のアドレスに、情報を載せて送り出すことを防ぐため）。あわせて、`Content-Security-Policy` を付けて、画面が、自分のサーバー以外へ接続・読み込みしないようにします（`render_ui` のフォームは、画像を表示できますが、外部から読み込むことは、同じポリシーで止まります）。
- **保存先のディレクトリは、所有者だけが読めます**（`~/.make-it-so`、艦のディレクトリ。モード 0700）。会話の DB・ログは、平文ですが、他のユーザーからは読めません（Windows を除く）。
- **リモートの接続先の検査。** `hosts.yml` の `destination` が、空・空白を含む・`-` で始まる場合は、拒否します（ssh のオプション注入を防ぐため）。接続の詳細（鍵・ポート・ユーザー）は、`hosts.yml` に書けない作りにしています。
- **逆トンネルは、リモートの `127.0.0.1` にだけ張り**、張れなかったときは接続を失敗させます。
- **アイコンは、ラスター画像だけ**を受け付けます。SVG は、スクリプトを含められるので、受け付けません。形式は、拡張子や申告された種類ではなく、中身の先頭のバイトで判定します。配信には `X-Content-Type-Options: nosniff` を付けます。サイズの上限があります。
- **リクエストのボディのサイズに、上限があります。**
- **タスク ID などの、パスに使う識別子は、英数字と `_`・`-` だけ**を受け付けます（それ以外は `400`）。
- **掲示板は、呼び出し元を、サーバーが埋め込んだ識別ヘッダーから判別します。** モデルの自己申告には頼りません。ヘッダーがない呼び出しは、推測せずにエラーにし、秘密の値がない呼び出しは、どのツールも動かす前に断ります。ただし、これは呼び出し元ごとの認証ではありません（上記）。
- **デバッグ用のルートは、設定で有効にしたときだけ**使えます（既定は無効）。
- **エージェントのプロセスは、サーバーが異常終了しても、残らない**ように起動します（Linux + claude で確認。ローカルとリモートの両方）。

## 利用者が気をつけること

- `server.host` を変えない。変えるときは、ネットワークの信頼できる範囲に限る。
- 確認が必要なクルーには、`permission_mode: default` を指定する。
- クルーに任せる `cwd` は、**失われても困らない範囲**にする。重要なデータのあるディレクトリを、そのまま `cwd` にしない。
- リモートホストは、他のユーザーと共有していないものを使う。
- 会話の内容は、プロバイダーに送られ、手元にも残ることを理解する。機密を含む内容は、扱いに注意する。
- Claude Code のワークスペースの信頼の設定（`~/.claude.json`）を、変えるときは、内容を確認する（[基本概念](concepts.ja.md#プロバイダーの違い)）。
- kiro-cli には、ツール呼び出しが実行されないまま終わる、間欠的な不具合があります。エラーも承認も出ず、静かに止まったように見えます。頻発するクルーは、セッションを再起動してください。

## 脆弱性の報告

脆弱性を見つけたときは、公開の issue ではなく、GitHub の**非公開の脆弱性報告**（リポジトリの「Security」タブ →「Report a vulnerability」）で連絡してください。詳しくは、リポジトリ直下の [`SECURITY.md`](../SECURITY.ja.md) を参照してください。
